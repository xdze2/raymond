# Devlog — 2026-05-31 — Structural refactor + new wiki

## What changed

The repo moved from a per-wiki tangle (each wiki carrying its own `frontend/`, its own JSONL catalogue, its own ad-hoc index scripts) to a shared-frontend layout with one JSON file per entry and a small set of tools that work for every wiki.

```
frontend/                    # shared, served verbatim
  index.html, style.css
wikis/<name>/
  wiki.json, axis.json
  catalogue/<slug>.json      # one entry per file (the source of truth)
  index.jsonl                # generated, gitignored
  media/, pages/, prompts/
tools/
  build_index.py             # catalogue/*.json → index.jsonl
  dev_server.py              # Flask: serves frontend + wiki + /api/health
  export.py                  # dist/<wiki>/ standalone bundle
```

Two surfaces from one codebase: the dev server overlays the shared frontend on a chosen wiki's data and exposes `/api/health`; the static export produces the same browsing experience without the API. The asymmetry is what step 10 of the migration plan (edit-mode UI) will hinge on.

## Why a fresh wiki (`megaprojects`)

`mobility_innov` and `data_atlas` were demo-only and worth more as historical record than as migration ballast. They moved to `archive/`. The refactor was executed against a new wiki, *Failed Megaprojects* — six bounded axes (`domain`, `era`, `region`, `political_system`, `failure_mode`, `current_state`), no freeform axes, 5 hand-written `explored` seed entries.

The `failure_mode × current_state` pair is doing the editorial work: it turns the wiki from a list of disasters into a typology of how ambition rots, with the card grid color-coded by what's physically left of each project.

## Schema landed

Entry files now look like:

```json
{
  "slug": "ryugyong-hotel",
  "title": "Ryugyong Hotel",
  "summary": "330-metre pyramidal hotel in Pyongyang…",
  "axes": { "domain": "habitat", "era": "1946_1989", ... },
  "status": "explored",
  "facts":  [{ "label": "Height", "value": "330 m, 105 floors" }, ...],
  "links":  [{ "label": "Wikipedia", "url": "https://..." }],
  "created": { "at": "2026-05-31", "by": "user:xdze2" }
}
```

The frontend distinguishes `explored` (solid border, full opacity) from `generated` (dashed border, dimmed). The modal renders facts as a label/value grid and links as a chip row — no prose, no markdown. The `status_axis` from `wiki.json` (`current_state` here) drives the colored dot on each card and the colored chip in the modal.

## Tooling decisions

- **`uv` for the Python env**, with a real `pyproject.toml`. Flask is the only runtime dep.
- **No build step on the frontend.** Vanilla JS module, relative paths only, served identically by Flask in dev and any static server in production.
- **`#<slug>` hash routing** on the frontend — added during the smoke test so deep-links work, kept because it's almost free and genuinely useful.
